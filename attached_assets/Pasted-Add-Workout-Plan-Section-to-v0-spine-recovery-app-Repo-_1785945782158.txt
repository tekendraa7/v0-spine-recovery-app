Step 2b — Sourcing exercise posters + videos (legally, without hardcoding copyrighted media)

For each exercise, add two optional fields to the data model:

posterUrl: a static demo image
videoId: a YouTube video ID for an embedded form-check clip

Poster images — use the free, open-license wger.de exercise database (CC-BY-SA, no API key required):

Endpoint: https://wger.de/api/v2/exercise/search/?term=<exercise name>&language=english&format=json
Or browse https://wger.de/en/exercise/overview/ to find matching entries and grab their image URLs directly.
If a specific machine exercise (e.g. "Chest Supported Row Machine") has no exact match, fall back to the closest generic movement (e.g. "seated row") or use a simple line-icon illustration instead of leaving it blank.

Videos — do not download or rehost any video file. Instead embed the official YouTube iframe player (https://www.youtube.com/embed/<videoId>), which is standard, permitted embedding — not reproduction. Two ways to populate videoId:

Best: search YouTube yourself (or let the agent use the YouTube Data API if you provide a free API key) for a short, reputable form-check video per exercise (e.g. from well-known trainer channels) and paste the video ID in.
Fastest to ship: leave videoId as an empty string for now and instead render a "Search demo video" button per exercise that opens https://www.youtube.com/results?search_query=<exercise name> proper form in a new tab — zero maintenance, and you can swap in a curated videoId later once you've picked a video you trust.

Either way, keep this data in lib/workout-data.ts so you can hand-edit any posterUrl/videoId yourself later without touching component code.
